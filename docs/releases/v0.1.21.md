## Mux v0.1.21

本版是面向 **Herdr Pulse 日常使用、安全确认与常驻刷新** 的补丁更新。以下说明覆盖自 v0.1.20 以来的实际变化：Pull / Push 的 Review 绑定目标，失败操作与提交草稿可恢复，TOKEN 首页和图表明确区分数据来源与读取状态，窄屏导航、Git 文件辨识以及账号 / Session 后台刷新进一步完善。沿用现有配置、账号切换服务和代理路由，不新增在线唤醒或付费请求功能。

### Git：确认的目标不会随后台刷新悄悄改变

- **Pull / Push 先准备目标，再打开 Review**：在后台读取并固定完整分支引用、HEAD、上游配置、远端名称与目标分支引用。确认页显示实际准备的分支、短 HEAD、远端与目标；首次 Push 还明确说明将设置上游，不再只根据界面上可能已经过时的分支摘要生成确认。
- **执行前拒绝过期确认**：Review 后切换分支（即使另一分支指向同一提交）、新增提交、修改上游配置，或删除首次 Push 选中的远端，都会拒绝执行并提示 `Git target changed; reopen Review`。需要重新打开 Review，由用户再次确认；不会自动重选目标、重试或继续执行旧确认。
- **只推送所确认的当前分支**：Push 使用固定的完整 `本地分支引用:目标分支引用`，不使用执行时浮动的 HEAD 或默认推送目标；`push.default=matching` / `remote.push` 不会扩大这次推送范围。首次 Push 仍选择远端并设置上游，不提供强制推送。
- **Pull 保留保守语义**：要求干净工作区，显式指定远端和目标，使用 `--ff-only --no-autostash`；分叉时不自动合并或暂存本地修改。常规 Pull / Push 必须有单一 `refs/heads/...` 上游，无上游或多上游配置不能进入可执行 Review；首次 Push 使用单独的远端选择流程。Git 的本地上游 `remote='.'` 仍受支持。
- **安全边界**：这些检查是尽力而为的执行前 stale guard，读取分支 / HEAD 时再次核对以避免混合身份，**不是仓库锁，也不能与外部 Git 操作形成原子事务**。它固定远端名称和引用，**不冻结 remote URL**；外部进程仍可能在检查后改变仓库或远端配置。执行前不要并行修改目标；超时后先检查真实仓库状态，再决定是否重试。

### Git：完整诊断、持久的最后结果与失败草稿恢复

- **保留 stdout 与 stderr**：成功操作的 hook / 远端反馈以及失败诊断均保留两路非空输出；同时有内容时，详情按 `stdout:` / `stderr:` 分段展示。status、Diff、Log 等机器解析仍只读取 stdout，不把诊断混进文件或历史数据。
- **`l` 查看最后一次操作**：详情保留动作、成功 / 失败、原仓库路径和完整可用输出。普通状态刷新、Diff / Log 读取、短提示到期不会覆盖该结果；切换仓库后详情仍标出原仓库，不把旧仓库的失败当成当前仓库状态。动作成功但随后刷新失败时，分别保留“动作成功”和“当前刷新错误”。没有操作结果时显示明确空状态或读取错误，不再误显示 Working。
- **失败后可以继续操作**：失败结束 busy / Working 状态并打开详情。短状态栏只显示摘要，长输出可在详情中滚动阅读。保留既有 120 秒 Git 超时与输出限制；stderr 达到 16 MiB 时明确提示截断，stdout 超限仍拒绝，不承诺无限保存命令输出。
- **多行提交消息不会因失败丢失**：`n` 打开提交表单，Enter 换行，Ctrl+Enter / Review 复核，再按 Enter / `y` 确认。提交失败后，首次关闭失败详情会重新读取 HEAD 与暂存区，并恢复原消息；必须再次 Ctrl+Enter / Review、再次确认，不能直接执行失败前的旧 HEAD / index。
- **复核失败也保留草稿**：没有暂存内容、有冲突或读取失败时，显示错误并回到 Files，不自动循环重试；处理后可再按 `n` 复核。再次用 `l` 查看旧错误、打开帮助或执行其他操作，不会触发自动恢复。
- **草稿生命周期明确**：每个 Pulse pane 只在本次运行内保留最近一份失败提交草稿，不写磁盘、不跨退出保存、不跨仓库复用。成功提交或明确取消恢复后的编辑表单会清除；显式提交另一份新消息会替换它。Review 页的 Esc / Edit 仍返回消息编辑，沿用 Git hooks、签名与暂存区检查。入队失败时保留原确认和消息，不通过自动重试隐藏错误。

Git 认证仍沿用本机 credential helper / SSH 配置，并禁用终端密码提示；需要交互认证时先在普通终端完成。新增、删除、重命名、二进制、权限变更和子模块仍使用整文件操作；冲突仍在外部解决后暂存。本版不增加图形提交拓扑、Stash、Rebase、Cherry-pick、分支删除、图形冲突编辑或逐行暂存。

### TOKEN：读取状态可信，网关与会话各算各的

- **区分 Loading / Ready / Stale / Unavailable / Partial**：网关首次读取中显示 Reading，首次读取失败显示 unavailable；已有成功数据后读取失败保留旧数据并标 stale。本地 Session 日志有警告且仍有可读会话时标 partial，没有可读会话时标 unavailable。
- **按当前页面显示真正相关的错误**：Home 检查实际显示的来源，订阅首页不因隐藏的网关失败报错；Sessions 只显示本地日志状态；Charts 同时检查网关和 Session。两源异常可以同时显示，例如 `GW stale · Sessions partial`，不互相覆盖。普通与迷你布局使用同一状态优先级。
- **未知或不可用不冒充零**：Home / Chart 首次加载与网关不可用时显示读取 / 重试提示，不画零柱、不打印真实 0；stale 时保留旧图并明确标记。缺少当前 Session ID / 日志继续显示等待识别，未知 token 显示不可用；只有成功读取且确实无请求或增量时才表示零。
- **首页重排而不改变统计范围**：统一按“账号卡（如有）→ 今日 Gateway 摘要、大数字、输入 / 输出与请求数 → 当前 Session 完整区块 → 网关缓存 / 速率 / 测量样本 → Call Health → Provider / Model 明细”排列。文字版健康计数合并为一行，仍保留成功率、比例条和 Compaction；简洁版保留各项实际数值。额度卡很长时仍需滚动，不承诺任意窗口高度都能展示所有区块。
- **标题明确来源和时间范围**：普通网关标题为 `GATEWAY TOKENS`，迷你布局为 `GATEWAY / TODAY`；Session 标明 `SESSION / ALL TIME`，Grok 保留 Active / Recent 区别。网关是今日经过 Mux 本地代理的请求统计，Session 是本地日志中的会话累计，两者不相加，也不是订阅剩余额度。Charts 的网关每小时请求数与 Session 今日每小时 token 增量分别缩放，柱高不能直接比较。
- **订阅账号首页自动精简**：Codex 使用 ChatGPT 登录、Grok 使用 OAuth 原生模型时，首页隐藏 Gateway / Call Health / Provider 明细，仅显示账号与本地 Session；切回 API 网关模式恢复。文字、简洁与迷你布局一致。按本地登录和默认配置判断，不仅因保存过订阅账号就隐藏；Grok 保存了 OAuth 登录但默认使用 API 模型时仍显示网关。客户端启动参数或运行中临时模型可能与默认配置不同；图表、Sessions 与 Claude / All 页面不因此改成新的统计范围。

缓存命中率、未知计数、待完成请求分母与 E2E 速率保留原有语义；本版不重新计算历史记录。Grok 原生日志的 API rate 与网关 E2E 输出速率仍分开，不把它们称为模型纯解码速度。

### 导航、窄屏与 Git 文件辨识

- **标题是当前页，按钮是切换目标**：顶部改为 `TOKEN [Git(g)]` / `GIT [Token(g)]`，去掉两个互斥分段页签的圆点标记。两页都可按 `g` 或点击方括号按钮双向切换，标题本身不是按钮；窄屏先保留页面标识，再简化目标标签和键位提示。Alt+1 / Alt+2 仍直接选择 TOKEN / GIT，`T` 直接返回 TOKEN。切回后保留统计子页、筛选、排序、滚动，以及 Git 文件、Diff、Log / 搜索状态；表单、确认和执行期间禁用切页。
- **TOKEN 底部先保留动作文字**：按标签实际显示宽度分配空间，依次省略快捷键、缩短为 `Sess`，极窄时才只显示键名；不再把 Sessions 过早压成只有 `(s)`。动作顺序仍是编辑、图表、会话、刷新、关闭，宽度足够时保留快捷键提示；Charts 的第二项返回 Home，Sessions 的第二项为 `Tokens(t)` / `Recent(t)` 排序，第三项为 `Home(s)`。绘制与鼠标命中使用同一组区域，调整窗口宽度后不会用旧的五等分区域解释点击。
- **常用 TOKEN 键位不变**：`1/2/3/4` 或 Tab 切换 Claude / Codex / Grok / All，`c` 切 Home / Chart，`s` 切 Home / Sessions，Sessions 中 `t` 改排序，`r` 刷新，`v` 切文字 / 简洁视图，`e` 在 Herdr 打开完整编辑器，`q` 关闭侧栏。
- **Git 概览更紧凑**：固定首行显示仓库目录名与分支下拉按钮；点击仓库名或按 `i` 查看绝对路径、分支、上游、领先 / 落后、Follow / Pinned 模式及当前 worktree 的本地 `FETCH_HEAD` 记录。无记录时显示 unknown；领先 / 落后依赖本地远端引用，状态轮询不自动 Fetch。`p` 固定 / 取消固定仓库；窄屏缩短模式标签并优先保留非零 `↑/↓`。
- **Git 操作更易辨认**：文本 Diff 区分 `Stage block(h)` 与 `Stage file(s)`，取消暂存 / 丢弃按对象区分文件和块；窄屏保留关键操作名。Stage all 仍在 `o` 菜单和 `a/A` 快捷键，不把当前文件的 Stage 按钮变成全仓库操作。
- **未选中也能分清重名文件**：不同完整路径的同名文件使用最短可区分后缀，例如 `src/git.rs` 与 `quick/git.rs`；无重名仍用 basename。同一文件同时出现在 Staged / Unstaged 不会被当成两个重名路径。选中项保留完整相对路径和重命名上下文，搜索仍匹配完整路径 / 原路径；长 Unicode 路径按显示宽度裁剪，续行点击仍指向正确文件。

### 常驻 Session：完整监听用事件，覆盖不足保守轮询

- Claude、Codex、Grok、Pi **四个既有日志根目录都存在、都是目录且全部注册成功**，并且监听运行健康时，才采用完整监听模式。文件事件以首个事件起算的固定 **150 ms** 窗口合并，持续事件不会无限推迟读取；成功采集后每 **30 秒**兜底读取，监听覆盖也每 30 秒重新确认 / 重建。
- 任一根缺失、不是目录、注册失败，或回调报告监听错误时，保留成功注册的部分监听，同时每 **2 秒**兜底采集与重试。目录删除 / 根集合改变会重新判断覆盖，不以“有一个 watcher”冒充完整监听，也不改为忽略缺失客户端目录。
- `r` 立即请求本地 Session 采集，不等 150 ms 合并窗口；采集期间的新手动请求保留到下一轮，不因唤醒合并丢失。
- Pulse 与完整编辑器 Usage 页均使用完整性 / 健康判断；Usage 原有配置刷新周期和 dirty throttle 保留，离开 Usage 释放监听，重开后恢复。日志增量解析与会话合并语义不变。

这是一项调度与正确性改进，不是已测得的 CPU / I/O 性能结论。缺少任一日志根的机器仍走两秒保守模式，不保证所有环境都会减少扫描。

### 账号：本地身份先显示，慢额度由唯一 worker 串行查询

- **先发布本地账号，再查询在线额度**：启动、选页、本地两秒采集与额度完成时重新读取身份；先显示当前本地账号和同身份缓存，不让慢 Codex / Grok 请求阻塞身份展示或侧栏导航。沿用原有保存、切换与额度服务，不从后台回写整份旧配置。
- **Codex 只明确刷新才查询**：启动、选择 Codex 页和本地定时更新不调用额度 RPC；`r` 或成功切换后的刷新才调用。查询目标优先已配置的 active Account，否则使用已保存的 live 登录；展示仍优先本地 live 登录。Claude / All 的 `r` 仅刷新本地采集，不额外查询账号额度。
- **Grok 自动与手动调度分开**：只在当前选中 Grok 且身份有效时自动查询；60 秒间隔从实际发起请求算起，失败不立即重试。`r` 可立即请求，切离 Grok 丢弃尚未开始的自动任务，但不取消已经执行的请求；同身份缓存可以继续保留。
- **只有一个额度 worker**：Codex / Grok 查询串行执行，每个客户端最多合并保留一个待执行任务；正在查询时重复手动刷新至多保留一次后续刷新。手动优先于自动，多个手动按请求顺序调度，不把所有点击排成长期 FIFO。
- **身份与代际共同保护结果**：发起前再次核对身份，完成后重新读取本地身份，只接受相同身份、相同代际的结果；迟到成功和错误都不会污染新账号，A→B→A 也拒绝旧一代结果。身份读取失败时使 key 无效；Grok 成功还核对返回账号，同一 Grok 身份仅旋转 token 不清缓存，身份改变则清旧额度与错误。
- **保留错误与凭据保护**：Grok 同身份查询失败保留缓存和错误，后续本地采集不会把错误清掉，同身份成功后恢复。Codex 沿用原服务的私有凭据刷新、增量配置更新和写 live 登录前的比较保护，避免覆盖外部切换后的登录；刷新失败只向仍匹配的卡片显示脱敏提示。worker 断连显示额度不可用，不自动重发；退出 Pulse 不等待慢网络请求，已有请求按既有超时自然退出。

### 验证范围与已知边界

发布前的本地验证在 **macOS 原生环境**完成：`--locked --all-targets --all-features` 回归合计 **512 项通过、7 项 ignored**，构建、Clippy 与格式检查通过。这个数字是本地结果，**不是 Windows 测试结果，也不代表真实厂商在线服务验证**。Windows 源码支持、Windows 原生 CI 与 Rust 1.88 MSRV 检查保留；各平台远端结果以对应 GitHub Actions 运行记录为准。

实际验证不只依赖渲染单元测试，还包含隔离临时 HOME / 日志 / 用量库 / Git 仓库中的原生 PTY：

- 28–80 列窗口、48→32→80 调整尺寸与真实鼠标按钮命中，检查页面切换、排序、刷新 / 关闭和 48 列账号菜单。
- 真实本地 bare remote：Review 后分支漂移被拒绝，重新 Review 后仅推送新的 B 分支；首次 Push 准备后移除远端被拒绝，不设置上游。Git 子进程回归另覆盖 HEAD / 上游漂移、双流 hook、本地上游和固定 refspec。
- 多行提交失败后消息保留、重新读取 HEAD / index 并要求 fresh Review；取消恢复后仍可查看持久错误，提示到期与刷新不会把详情变成 Working。
- 损坏用量库时明确 unavailable；已有旧数据的读取失败保留图表并标 stale，恢复库后手动刷新恢复数值，不拿虚假零冒充成功读取。
- 实际 Grok 日志由 110 累计到 330，事件与手动刷新可见；完整编辑器 Usage 的日志刷新、离开 / 重开后 333 读数，以及同名 / 长 Unicode Git 路径与 Diff 目标。
- 隔离的实际 Pulse + 本地 app-server 协议 fixture：A 的额度请求被阻塞时仍展示 B 的本地身份并可导航；迟到 A 结果被拒绝，外部 B 登录未被覆盖，退出不等待被阻塞额度请求。受控 worker 回归覆盖代际、串行、合并、优先级和缓存；官方 RPC 形状 fixture 覆盖失败保留额度、token 刷新与脱敏。

**未验证的部分**：未调用真实厂商计费 / 额度服务或真实 OAuth；未在真实 Herdr 环境验收焦点跟随集成。已聚焦 Claude / Codex 的首屏只以真实日志 Reader + Monitor 的临时渲染检查补充，不能视为 Herdr 焦点集成实测。本版不宣称 CPU / I/O 降幅，也不改变已有账号或代理生产服务的语义。

测试隔离同步修正：Codex 测试 Sandbox 默认使用明确停止状态的 daemon helper，避免误调用机器上安装的真实 CLI；metering 失败用例复用单个共享 Writer，避免 macOS WAL 异步打开 / 关闭死锁。这些是验证 fixture 修复，不是代理新增功能。macOS / Linux 全量回归步骤的超时上限调整为 10 分钟，覆盖编译与串行测试；测试 job 仍有 20 分钟上限，不跳过测试或放宽断言。Git 确认说明以不可变字符串紧凑保存，保持原操作与草稿的值所有权，兼容 Windows Clippy 的布局检查。

**v0.1.21 不提供 Windows Release 二进制或 ZIP 包**；这不等于移除 Windows 源码兼容或 Windows CI。Windows 用户可从本版本源码构建；历史 Windows 包仍属于其原版本。GitHub 自动生成的 Source code 归档不是额外平台二进制。macOS Intel 仍需源码构建。

源码最低要求 **Rust 1.88** / Cargo。Herdr Pulse 插件支持 macOS / Linux，需要 **Herdr 0.7.0+**；Git 工作流需要系统 **`git`**。发布版脚本需 Bash、curl、tar，以及 sha256sum 或 shasum，下载安装时核对 SHA-256。

macOS / Linux 安装或更新全局 Mux：

```sh
curl -fsSL https://raw.githubusercontent.com/Sunmedalia/mux/main/install.sh | bash
```

在 **Herdr 普通终端**安装或更新发布版 Pulse：

```sh
curl -fsSL https://raw.githubusercontent.com/Sunmedalia/mux/main/install.sh | bash -s -- herdr
```

也可由 Herdr 下载并安装版本匹配的插件，无需本机 Rust / Cargo：

```sh
herdr plugin install Sunmedalia/mux
```

上述脚本默认下载最新 Release；固定本版可将管道右侧改为 `MUX_VERSION=v0.1.21 bash`（安装 Pulse 则为 `MUX_VERSION=v0.1.21 bash -s -- herdr`）。Herdr 插件安装按其 manifest 版本下载对应发布包；之前使用本地源码链接同名插件、现在改用发布版安装时，先执行 `herdr plugin unlink mux`。

**本地源码链接用户**在原 checkout 更新源码，然后在 Herdr 普通终端运行：

```sh
git pull --ff-only
bash scripts/install-herdr.sh
```

此脚本构建当前 checkout（包含本地修改），更新 Mux 并把插件链接到该目录；请保留该目录。默认快捷键仍为 **Ctrl+B，再按 u**（自定义 prefix 使用自己的 prefix），已有 Mux 键位保留，冲突不会被覆盖；可用 `bash scripts/install-herdr.sh --key prefix+shift+u` 指定空闲键位。也可执行 `herdr plugin action invoke mux.open` 打开 / 关闭侧栏。

**升级后关闭并重新打开旧 Mux / Pulse pane**：已经打开的进程不会因文件替换自动更新，失败提交草稿也不会跨退出保留。安装不会关闭工作中的 agent 或重启 Herdr。若需要把正在运行的后台代理换成新版程序，先等请求结束，再执行 `mux proxy stop`、`mux proxy start`；本版的 Pulse 展示与刷新改进不要求改写客户端路由或模型配置。
