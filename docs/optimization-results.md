# 优化验证记录

验证日期：2026-10-05。本机为 Apple M4 / macOS ARM64，默认 Rust 1.95.0，最低版本检查使用 Rust 1.88.0。结果来自本地测试与临时服务，不请求真实模型厂商。

## Tokenizer 基准

执行 `cargo test --locked --bin mux tokenizer_benchmark -- --ignored --nocapture`，使用 debug 构建。预热后，各路径取七次耗时的中位数。原路径每次创建 cl100k tokenizer，新路径复用 tokenizer；每次同时断言 Token 数完全一致。

| 输入 | 每次重建 | 缓存路径 | 本机提升 |
| --- | ---: | ---: | ---: |
| 短消息 hello | 213,611 µs | 86 µs | 2,483.8 倍 |
| hello world 重复 10,000 次 | 291,206 µs | 88,526 µs | 3.3 倍 |

这些数字只衡量本机估算函数，不包含工作队列、HTTP、模型推理或冷启动初始化，不代表端到端响应时间。长上下文仍需执行编码，收益小于短文本。性能数字不作为 CI 硬阈值。

非流式用量统计改为共用入口读取的正文与 JSON 解析结果，取消观察器的第二份正文缓冲；这是代码层面的内存优化，本次未测量峰值 RSS。

## 第二轮优化

SSE 解析改为按换行分段批量复制，只在可能完成事件的位置检查分隔符，并在扩展缓冲前检查单事件大小。UTF-8 分片、混合换行、原始事件字节和每事件 1 MiB 限制保持一致；单个网络块可包含多个事件且总大小超过 1 MiB。

同机 debug 构建执行 `sse_decoder_benchmark`，以 4 KiB 网络分块，预热后取七次中位数，并逐次断言新旧事件内容一致：

| 输入 | 逐字节解析 | 批量解析 | 本机提升 |
| --- | ---: | ---: | ---: |
| 单个约 234 KiB 中文长事件 | 4,057 µs | 862 µs | 4.7 倍 |
| 10,000 个短事件 | 8,530 µs | 6,607 µs | 1.3 倍 |

该基准只衡量解析器，不代表完整代理或模型生成速度。

会话记住的 Provider 被禁用、删除或从同步路由移除时，清除过期绑定，角色模型回到当前默认 Provider；显式选择不可用模型仍返回错误。新增回归覆盖这三种变更。

后台状态检查合并重复工作；排队同步或开始代理操作时使旧检查结果失效，避免旧错误覆盖更新的成功状态。回归包含旧检查在新同步完成后返回的情形。

第二轮共 365 个单元测试及 28 个集成测试通过，6 个手动测试默认忽略，其中 SSE 基准已单独执行。Clippy、格式、Rust 1.88 及 Windows GNU 交叉检查通过；远程 CI 和原生平台验证范围同上。

一次全套复测中，已有 Grok 模拟服务测试报告监听地址占用；该模拟服务原本就占用此地址，日志不足以确定为何该次健康检查未识别它。单独重跑及随后默认并发全套重跑均通过。本轮未修改该测试或代理生命周期逻辑，保留记录以便后续定位。
